# ตรวจปัญหาแชทบน Vercel

## ข้อค้นพบจากการตรวจครั้งนี้

- ข้อความ “AI ใช้เวลาตอบนานเกินไป” มาจากการตัดคำขอฝั่งเบราว์เซอร์ ไม่ได้ระบุว่าติดอยู่ที่ Gemini หรือฐานข้อมูล
- ก่อนแก้ เบราว์เซอร์และ Vercel route ใช้ขีดจำกัด 30 วินาทีเท่ากัน จึงไม่มีเวลาเผื่อให้ผลตอบกลับถึงมือถือ
- Middleware เรียก Supabase Auth ก่อน API แชท ทั้งที่ API ตรวจสิทธิ์ลูกค้าจาก QR เอง การตรวจบัญชีนี้เป็นงานเพิ่มเติมที่ไม่จำเป็นสำหรับแชท
- ทดสอบฟังก์ชัน Gemini จริงด้วย key ในเครื่องและเมนูสมมติสำเร็จก่อนแก้ประมาณ 12.25 วินาที และหลังแก้ประมาณ 9.67 วินาที การทดสอบสองครั้งนี้ไม่ได้พิสูจน์ว่าการแก้ทำให้ Gemini เร็วขึ้น หรือยืนยัน key/เครือข่ายของ Vercel
- อัปเดต 27 ตุลาคม 2026: ภาพ runtime log ที่ผู้ใช้ส่งมายืนยันว่า Gemini ตอบ HTTP 503 หลังประมาณ 8.56 วินาที โดยใช้ gemini-3.1-flash-lite เป็นข้อผิดพลาดจากผู้ให้บริการในคำขอนี้ ไม่ใช่การตัดเวลาของเบราว์เซอร์

## การแก้ไข

- ข้ามการ refresh บัญชีเฉพาะ /api/customer/chat โดยยังตรวจ QR, อายุ QR, โควตา และตรวจ QR ซ้ำหลัง AI ตอบเหมือนเดิม
- จำกัดการรอ Gemini 20 วินาที รวมการอ่าน response body; Vercel route 45 วินาที; เบราว์เซอร์ 55 วินาที
- หาก gateway ส่งข้อความหรือ HTML แทน JSON จะแสดงข้อผิดพลาดที่เหมาะสมและเก็บคำถามไว้ให้กดลองใหม่
- เมื่อ Gemini ตอบ HTTP 503 จะลองใหม่อัตโนมัติอีกไม่เกิน 1 ครั้ง รอสุ่ม 1–1.5 วินาที และเคารพ Retry-After หากผู้ให้บริการระบุเวลานานกว่า ทั้งสองครั้งรวมช่วงรอและอ่านคำตอบอยู่ในเพดาน 20 วินาทีเดิม หากเวลารอไม่พอจะไม่ส่งซ้ำ
- ไม่ลองใหม่อัตโนมัติเมื่อ Key/สิทธิ์มีปัญหา, โควตาเต็ม (429), timeout, network error หรือคำตอบผิดรูปแบบ
- การส่งซ้ำนี้อยู่ในคำขอเดิม จึงนับโควตาของแอปเป็นหนึ่งคำถาม และยังตรวจ QR ซ้ำก่อนส่งคำตอบให้ลูกค้า การเรียก Google อาจเกิดขึ้นสองครั้ง
- เพิ่ม log ระบุช่วงทำงานและรหัสข้อผิดพลาด โดยไม่บันทึก key, QR, ข้อความสนทนา หรือ response body จากผู้ให้บริการ

## ทดสอบหลัง deploy

1. Push โค้ดแล้วรอ deployment ใหม่เป็น Ready ตรวจว่าลิงก์ที่เปิดใช้ deployment/branch ที่ต้องการ
2. ใน Vercel Settings > Environment Variables ตรวจว่ามี GEMINI_AI_API_KEY ใน environment ที่กำลังทดสอบ หากมี GEMINI_MODEL จะมีผลเหนือค่า default ในโค้ด ปัจจุบัน default คือ gemini-3.1-flash-lite การลบตัวแปรออกจากไฟล์ตัวอย่างไม่ได้ลบค่าที่ตั้งบน Vercel
3. หลังเปลี่ยน Environment Variables ให้ redeploy แล้วเปิดหน้าใหม่บนมือถือ สแกน QR ของโต๊ะที่เปิดอยู่และส่งคำถามหนึ่งครั้ง
4. หากยังไม่สำเร็จ เปิด Vercel Logs กรอง /api/customer/chat ตามเวลาเกิดเหตุ แล้วดู [customer-chat] และ [customer-ai] ที่มี requestId เดียวกัน

## อ่าน log

elapsedMs เป็นเวลาสะสมตั้งแต่เริ่ม route; log ของ [customer-ai] นับตั้งแต่เริ่มเรียกผู้ให้บริการ ผลต่างระหว่างขั้นบอกเวลาของขั้นก่อนหน้า

| stage/code | ความหมาย |
| --- | --- |
| read_request | เริ่มอ่านและตรวจรูปแบบคำขอ |
| session_and_menu | เริ่มตรวจ QR, โควตา และดึงเมนู |
| provider | เริ่มรอ Gemini |
| session_recheck | ได้คำตอบแล้ว เริ่มตรวจว่า QR ยังใช้ได้ |
| complete | พร้อมส่งคำตอบกลับ |
| event: retry | เตรียมลอง Gemini ครั้งที่ 2; retryDelayMs คือเวลารอก่อนส่งซ้ำ |
| AI_TIMEOUT | Gemini ไม่เสร็จภายในเวลาที่กำหนด |
| AI_NETWORK | เชื่อมต่อผู้ให้บริการไม่สำเร็จ |
| AI_RATE_LIMIT | ผู้ให้บริการส่ง HTTP 429 |
| AI_PROVIDER_HTTP | ดู httpStatus เช่น 400/401/403/404/5xx เพื่อแยกปัญหาการตั้งค่า/สิทธิ์/บริการ |
| AI_INVALID_RESPONSE | คำตอบไม่ผ่านรูปแบบที่ระบบยอมรับ รวมกรณีคำตอบถูกตัด |
| CHAT_REQUEST_FAILED | ปัญหาส่วนอื่น ดู stage และ status ประกอบ |

กรณี route จัดการข้อผิดพลาดเอง response จะมี X-Chat-Request-Id สำหรับเทียบกับ log; ข้อผิดพลาดที่ Vercel สร้างเองอาจไม่มี header นี้ หากไม่มีแม้แต่ read_request ยังระบุไม่ได้ว่าคำขอมาถึง route หรือไม่ ต้องตรวจ deployment และ network เพิ่ม

ส่งเฉพาะ log ที่เกี่ยวข้องและเวลาที่ทดสอบ ไม่ต้องส่ง API Key หรือค่า Authorization การทดสอบเต็มเส้นทาง production ครั้งนี้ยังไม่ได้ทำ เพราะไม่มี QR ทดสอบที่ผู้ใช้จัดเตรียม และระบบอนุมัติอัตโนมัติไม่อนุญาตให้ดึง session token จากฐานข้อมูลเพื่อใช้ทดสอบ

## ผลตรวจในเครื่อง

- หลังเพิ่ม retry: npm test ผ่าน 365/365 รวมการจำลอง 503 แล้วสำเร็จ, ล้มเหลวซ้ำ, หมดเวลาระหว่างรอ/อ่านคำตอบ, Retry-After และปิดโต๊ะระหว่าง retry
- TypeScript (tsc --noEmit): ผ่าน
- git diff --check: ผ่าน
- ก่อนเพิ่ม retry เคยเรียก Gemini จริงด้วยข้อมูลสมมติได้ HTTP 200 และ parse คำตอบสำเร็จ; รอบนี้ตรวจพฤติกรรม retry ด้วยการจำลองข้อผิดพลาด ยังไม่ได้ยืนยัน retry บน Vercel
- ยังไม่ได้ตรวจ lint/build ใหม่ หรือ deploy การเปลี่ยนแปลงครั้งนี้

## ตรวจหลัง deploy การลองใหม่เมื่อ 503

หากเจอ [customer-ai] ที่ event เป็น retry แล้วตามด้วย [customer-chat] stage complete แปลว่าลองใหม่สำเร็จ หากยังล้มเหลว ดู code, httpStatus และ attempt ใน log ของข้อผิดพลาด การลองใหม่ช่วยรับมือเหตุขัดข้องชั่วคราว แต่ไม่รับประกันว่าจะสำเร็จเมื่อ Gemini ยังไม่พร้อม
