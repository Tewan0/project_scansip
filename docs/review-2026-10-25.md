1. ใช้บัญชีที่ยังไม่มีร้าน เรียก createStoreOnboarding โดยส่ง slug ยาว 201 ตัวอักษร

ผลกระทบ: ร้านสร้างสำเร็จแต่ QR/การใช้งานของลูกค้าผ่าน slug นั้นถูกปฏิเสธ และมีข้อมูลเวลา/พร้อมเพย์ผิดรูปแบบในฐานข้อมูล นี่เป็นปัญหาความถูกต้องของข้อมูลร้านที่เจ้าของสร้างเอง ไม่พบการเข้าถึงร้านอื่นจากกรณีนี้

แนวทางแก้: ใช้ตัวตรวจข้อมูลร่วมกันสำหรับ onboarding และ settings โดยตรวจชนิด ความยาวชื่อ/slug เวลา และพร้อมเพย์; ตรวจซ้ำหลังสร้าง slug อัตโนมัติจากชื่อ เพิ่มกรณีขอบเขต 200/201 ตัวอักษร และแปลง database errors เป็นข้อความที่ไม่เปิดเผย SQL ภายใน

1. พนักงาน A เปิดหน้าจอที่แสดงรอบ A ของโต๊ะ 1
2. พนักงาน B ปิดรอบ A แล้วเปิดรอบ B ซึ่งยังไม่มีออเดอร์

### 3. ควรเสริม — API เรียกพนักงานยังอ่าน body เต็มก่อนตรวจ QR

ตำแหน่ง: app/api/customer/requests/route.ts บรรทัด 9

ทดสอบในเครื่องด้วย JSON stream ขนาด 262,240 bytes, Content-Type: text/plain และ QR ที่ใช้ไม่ได้: route อ่านครบทุก byte แล้วจึงตอบ 403 ไม่มี database write จากกรณีนี้

ผลกระทบ: ผู้ที่ไม่มี QR ใช้งานได้ก็ยังทำให้แอปอ่าน/parse payload ที่ไม่จำเป็นได้ เส้นทางนี้ยังไม่ใช้ readLimitedJson แบบเดียวกับออเดอร์และแชท ไม่ได้ทำ load test และผลนี้ไม่ใช่หลักฐานว่าเซิร์ฟเวอร์ล่ม; ข้อจำกัด payload ของโฮสติ้งอาจช่วยจำกัดขนาดอีกชั้น

แนวทางแก้: ใช้ readLimitedJson พร้อมเพดานเล็กตามข้อมูลที่จำเป็น เช่น 8–16 KiB และรับ application/json เท่านั้น ก่อนเปิด transaction ตรวจ QR; ทบทวนเส้นทางสาธารณะอื่นที่อ่าน body ก่อน auth เช่น DELETE /api/upload ด้วย

### 4. ต่ำ — ตรวจไฟล์รูปจาก MIME ที่ผู้ส่งระบุ แต่ไม่ตรวจเนื้อไฟล์

ตำแหน่ง: lib/upload-policy.ts บรรทัด 18

สร้าง File ที่มีข้อความ not an image แต่ระบุ image/png: validateImageUpload ยอมรับไฟล์นี้ ขนาดไฟล์และรายการ MIME ถูกจำกัดแล้ว แต่ยังไม่มีการตรวจ signature หรือ decode ว่าเป็นภาพจริง

ผลกระทบที่ยืนยันได้: ไฟล์ที่ไม่ใช่ภาพผ่านตัวตรวจและไปถึงขั้นอัปโหลดได้ อาจทำให้รูปเสียหรือใช้พื้นที่เก็บไฟล์ที่ไม่ต้องการ ไม่ได้ยืนยัน XSS หรือการรันโค้ดจากกรณีนี้

แนวทางแก้: ตรวจเนื้อไฟล์/ถอดรหัสภาพ พร้อมจำกัดมิติภาพก่อนบันทึก; ตั้ง allowed MIME และ file size ที่ bucket เป็นการป้องกันอีกชั้น ปัจจุบัน bucket ทั้งสองค่าเป็น null แต่การอัปโหลดผ่านแอปยังจำกัด 5 MiB และสิทธิ์ผู้ใช้ตามเดิม
